# 远程 MCP（云端 AI 连接）

> 专题设计，默认关闭。下文菜单步骤对应传统连接管理界面，当前 Mac 使用“Skill 与 MCP”卡片，不把旧菜单写成当前必备入口；现行本机连接见 [OPERATIONS](OPERATIONS.md)，账号隔离见 [DATA-AND-SECURITY](DATA-AND-SECURITY.md)。

让云端 AI（如 Grok Bot、Claude、ChatGPT 等支持远程 MCP 的客户端）在 Noteford 运行期间，通过公网 HTTPS 只读访问你授权的会话。默认关闭。

## 安全模型

| 层 | 做法 |
| --- | --- |
| 传输 | MCP streamable HTTP，`/mcp`；服务只绑定 `127.0.0.1:8765`，经 Cloudflare Tunnel 暴露；校验 Host/Origin |
| 授权协议 | OAuth 2.1：授权码 + PKCE(S256)、动态客户端注册（RFC 7591）、刷新令牌轮换、令牌撤销（RFC 7009）、授权服务器元数据（RFC 8414）与受保护资源元数据（RFC 9728） |
| 用户确认 | 授权页要求输入 Noteford「设置 → AI 连接 → 远程连接」生成的 8 位验证码（5 分钟、一次性；单请求错 5 次锁定，累计错 10 次作废当前验证码），通过后桌面端显示 AI 名称，用户选择可读范围并确认后才签发授权码 |
| 范围 | 每个令牌绑定一个 `mcp_access.json` 连接（会话白名单），与本机 stdio MCP 同一套校验；所有工具只读 |
| 撤销 | 撤销远程授权，或撤销其绑定的连接，下一次请求即 401 |
| 存储 | `data/mcp_remote.store` 整体 AES-256-GCM 加密；Windows 的数据密钥由 DPAPI（当前用户）保护存于 `data/mcp_remote.key`；macOS 的数据密钥在登录钥匙串，磁盘上只留标记；令牌/刷新令牌/授权码/验证码只存 HMAC-SHA256 摘要；访问日志关闭 |
| 管理接口 | `127.0.0.1:8766`，仅桌面端持有每次启动随机生成的密钥（环境变量传入、不落盘）；**不得经隧道暴露** |

令牌有效期：访问令牌 1 小时，刷新令牌 30 天（每次刷新轮换），授权码 5 分钟，授权请求 15 分钟。

## 连接流程（用户视角）

1. Noteford：设置 → AI 连接 → 远程连接，填公网地址并打开开关，复制「MCP 地址」`https://<域名>/mcp`。
2. 在 AI 客户端添加该远程 MCP；客户端会打开授权网页。
3. Noteford 里点「生成验证码」，把 8 位码输入网页。
4. Noteford 出现「某某 AI 请求只读访问」，选择范围（新建“全部已同步内容”连接，或沿用已有连接的会话白名单）→ 确认授权。网页自动回到 AI，连接完成。
5. 不再使用时在同一页面撤销。

## 与商用的差距 / 后续

- 当前已有产品账号与工作区隔离，远程连接也不能跨工作区继承授权。云端客户端兼容和公开服务验收需单独完成，不能由本机 stdio 测试推定。
- 远程可用性依赖电脑在线、Noteford 运行和隧道在线。
- 建议上线前对授权页和 OAuth 端点做第三方安全评估，并加速率限制（Cloudflare WAF 规则即可）。
