# 数据归属与安全边界

适用对象：用户与维护者。本文描述当前源码的存储和权限，平台安装与验收范围另见 STATUS，不构成已完成的公开隐私政策；商业发布缺口见 [STATUS](STATUS.md)。

## 数据归属与目录

微信原始数据仍属于本机微信目录，Noteford 只读该来源并在自己的数据根目录存放副本和派生数据。普通 NSIS 安装默认使用 `%LOCALAPPDATA%\Noteford`；单文件夹布局可把程序放在 `<根目录>/app/`、数据放在父目录。实际目录的判定顺序和迁移前核对步骤见 [OPERATIONS](OPERATIONS.md)；Mac 使用 `~/Noteford/Data` 作为专用私有数据根，源码根的其他位置不得存放正式资料；Data 不提交或打包。下表相对当前账号资料工作区，产品账号隔离见本文末尾。

| 数据根目录内 | 内容与敏感性 |
| --- | --- |
| `config.local.json` | 本地配置、来源位置、资料库配置 |
| `data/` | 资料库清单、旧群日报历史文件（已不再生成）、运行状态 |
| `libraries/<资料库 ID>/data/` | 账号快照、累计原始消息归档、明文索引、媒体缓存 |
| `libraries/<资料库 ID>/secrets/` | Windows/旧版布局；Mac 当前密钥仅持久保存在钥匙串，旧文件仅用于受校验迁移 |
| `secrets/` | 本地 API Token等 |

未关注会话的已观察到消息也保存在原始归档；取消关注不等于删除历史。两代加密快照、一代解密快照的保留规则不影响累计归档。删除程序文件不等于删除数据；删除整个数据根目录会失去索引、快照、密钥，但不删除微信自己的原始数据。

没有通用的一键备份恢复界面；离线恢复与 Mac 专用完整卸载是不同流程，见本文对应章节及 OPERATIONS，不能把卸载当作排障步骤。移动、清理或备份前应先确认实际目录并彻底退出程序；不要为排障盲删数据。Windows 账号和磁盘被读取时，明文索引及密钥材料可能暴露。不要提交、公开分享或放入普通诊断包、公开 Issue 和未经核对的云同步。

## 本机进程权限

Electron 页面只调用受限 IPC；主进程保管本地 API Token，并通过 `127.0.0.1` 请求 Python 服务。除健康检查外，本地 API 要求 Token。MCP 不持有这个 Token；它读取已建立的索引时，必须核验当前产品工作区租约和连接授权范围，Mac 与 Windows 都不能绕过账号隔离。任何有权运行本机 MCP 客户端并读取该数据目录的程序，都可能取得敏感会话内容。

本地媒体协议只允许从已管理的资料库缓存位置取文件。远程头像和卡片图片只接受允许域名的 HTTPS 地址并拒绝重定向；这可能让某些图片缺失，不能因此放宽来源校验而不复核风险。

macOS 权限页仅在点击「自动化 / 授权」后，由 Noteford 主进程通过原生线程向「系统事件」和「微信」各发送读取应用名称的 Apple Event；请求不经过外部 `osascript` 或 Python 探针，不在此步骤退出微信。请求先用 `AEDeterminePermissionToAutomateTarget(..., true)` 询问，允许后发送真实事件；微信未运行时先提示用户打开。状态检查使用同一进程的 `AEDeterminePermissionToAutomateTarget(..., false)` 分别查询两个目标，不复制或查询 TCC 数据库中的授权记录。原生请求未完成时，界面约 1 秒后打开自动化设置并恢复重试入口，同一未结束的请求不会重复排队。

目标通过主进程内的 `NSRunningApplication` 按 bundle id 找到当前 PID，再构造 `typeKernelProcessID` 描述符；权限查询使用 wildcard event class/id，确认该目标的完整自动化授权。避免让 Apple Event Manager 解析旧的 bundle 注册记录。系统事件空闲退出后会先唤起该后台系统服务，轮询不会启动微信。两个目标的被动检测分别限时，超时不复用旧的已授权结果、不重复堆积原生调用，也不丢弃另一目标已返回的结果。

「完全磁盘访问 / 授权」打开对应设置页，并在访达优先定位 `/Applications/Noteford.app`（未安装时回退到运行中的 Noteford 包），由用户点「+」添加、开启并重启。打开设置或能列出微信目录不代表已授权；只有主进程实际读到受保护的 TCC 文件头才显示已授权，只读取 16 字节，不解析授权记录，也不保存读取内容。可选的同进程 `TCCAccessPreflight` 只作为重启提示：策略允许但文件仍拒绝时显示「需要重启 Noteford」。这是非公开接口，缺失、超时或未知结果都不算授权；用户打开设置后仍可手动点击「已打开开关？重启 Noteford」。重启后重新打开并读取受保护文件才变绿。

读取同时覆盖用户目录及 `/Library/Application Support/com.apple.TCC/TCC.db`；在把用户级 TCC 数据库移入 ProtectedSystem 的系统上，原用户路径可能不存在。任一受保护文件实际返回内容才算通过；两个路径缺失、拒绝或错误均不放行，不根据目录存在或设置开关推断成功。

以下两段为早期 ad-hoc 原型风险记录，不是当前打包配置；现行 Mac 固定 Developer ID 签名，见 [OPERATIONS](OPERATIONS.md)。

历史 Mac ad-hoc 包没有 Team ID，因此主应用、helper 和独立可执行文件保留 Apple Events entitlement，并允许加载随包重签的原生库（`disable-library-validation`）；这放宽了 Hardened Runtime 的库签名团队限制，改用同团队 Developer ID 签名时应移除此例外。打包先核对原始 `libffmpeg` 字节，再从内到外重签，最后执行 `codesign --verify --deep --strict`，失败即中止。Mac 配置 `identity: null`，避免 electron-builder 在此后另选证书重签。

Ad-hoc 的默认 designated requirement 绑定 cdhash；包内容改变会使旧 TCC 记录不匹配。仅 identifier 的固定 requirement 虽然可写入签名，但不能认证发布者，任何同标识代码都可能满足它，因此不采用。应用读取自身签名元数据并在用户数据目录保存上次 cdhash；签名变化或使用 ad-hoc 且权限缺失时给出旧授权提示，不声称已经枚举到重复记录。正式分发宜采用稳定的 Developer ID 签名；requirement 的身份含义见 [Apple TN3127](https://developer.apple.com/documentation/technotes/tn3127-inside-code-signing-requirements)。

权限页每秒刷新，主进程在 `browser-window-focus` / `did-become-active` 和请求完成时重查并推送结果；刷新共用进行中的检测，焦点变化可追加新检测，前端丢弃较旧序号的结果。

MCP `read_image` 仅按已授权账号和消息读取本机已解析图片缓存，单张不超过 8 MiB，并在返回前再次核验授权。路径由索引中的媒体标识推导且限制在该库缓存目录内，不接受任意路径或 URL。调用会把选定图片提供给 AI 客户端，客户端可能发送给其模型服务；此能力不自动调用、不改变已有授权、不提供视频帧或微信云端下载。

## 向外部服务发送的内容

- **MCP 客户端**在本机读取后，可能再把结果发送给其自身模型服务。连接前应查看客户端的隐私设置；聊天文本不能被当成客户端指令。
- **应用更新**：Windows 使用更新仓库；Mac 使用需产品资格验证的正式 HTTPS 更新通道。更新文件不包含聊天数据，鉴权凭据不进入 URL 或日志。

图片、语音和视频依赖密钥、解码器及源文件仍存在；缩略图或媒体类型不等于完整内容已被解码。微信格式或密钥布局变化可使读取失败。Mac 已有正式签名、公证与钥匙串保护记录；这不证明所有机器兼容、通用备份恢复或法律与隐私审查已完成，验收范围以 STATUS 为准。


## 官方 MCP 连接授权（开发版）

设置页生成 `data/mcp_access.json`，保存连接 ID、标签、账号、scope 及启停状态。scope=all_synced 只涵盖已选入 Noteford（following/paused）的会话历史和后续入库内容，不读取未选会话的旧缓存；旧 selected 连接取明确授权会话与已选范围的交集。暂停会话保留历史可读，不恢复同步。默认拒绝未授权连接；列目录、读消息、搜索、状态、增量及原消息回查均应用范围检查。撤销在后续调用生效。

连接 ID 是本机协议的授权句柄，不是远端凭据。该功能不隔离同 Windows 用户下能直接读取/修改数据文件的其他程序；外部 AI 必须遵守插件只通过 MCP 访问的规则。不要把这个范围控制宣传成文件系统沙箱。

索引中的 mcp_changes 只保存变更序号、消息 ID、账号/表标识、操作类型和版本哈希，不复制正文；当前无自动清理，随索引变化增长。MCP 调用仍保持索引只读，授权只由桌面管理。导出插件不包含微信密钥或聊天正文，但与本机连接绑定，不作为公开通用发行包。

MCP 内容分类工具 `list_content` 在 SQL 查询阶段限制当前连接授权的资料库及会话，随后再提取、去重和统计，避免相同链接合并时泄露未授权会话出处。每次请求重新读取授权，撤销立即生效；不返回本地附件路径，不自动访问原链接。

增量游标绑定当前有效的已选会话集合，选入或移除会话后返回 `cursor_reset_required`；旧 all_synced 游标升级时也可能失效。客户端必须报告并重新读取已选历史，不能静默跳到现在。授权不因重连自动扩大。

## 同步回执、诊断与备份

每个资料库 `data/state/sync.json` 只保存运行状态、时间与固定错误分类，不写异常原文、源路径、聊天或凭据。异常重启保留最近成功时间并标记中断。`data/runtime/writer.lock` 是操作系统持有的服务写入互斥锁，进程退出自动释放；不是权限或文件系统安全边界。

离线备份清单包含相对路径、大小与 SHA-256；备份本体包含私密数据与密钥，不能作为公开诊断附件。恢复仅生成新的待验副本，不会切换或覆盖现用目录。步骤及局限以 [OPERATIONS](OPERATIONS.md) 为准。`diagnose` 已去除微信进程命令行与路径；服务启动失败也不把原始 stderr 拼接到界面错误中。

## 本地 MCP 配对（2026-10）

本地 MCP 不再以连接 ID 作为永久凭证：导出配置只含一次性配对令牌，首次使用须用户在 Noteford 原生弹窗中确认连接，无需验证码。弹窗仅显示客户端名称与连接请求，默认拒绝；名称由客户端声明，用户应仅允许自己刚刚发起的连接。程序路径、账号及范围快照由后台核验并绑定，不在弹窗展开。凭证与请求加密存于 `data/mcp_local.store`。Windows 用 DPAPI 保护密钥；macOS 把同一把密钥放进登录钥匙串，磁盘上的 key 文件只是标记。索引键使用摘要，自动连接令牌仅保存在此加密存储中。局限：同一 Windows 用户下、能冒充同一程序路径的恶意进程仍无法与真实客户端区分；`mcp_access.json` 本身未加密，但范围被改宽时授权自动失效。

Mac 后台的配对请求/连接列表检查使用禁止 UI 的钥匙串访问，旧登录钥匙串与 Data Protection 查询都受约束；未建立配对库时不创建密钥。授权失效只返回固定错误，不循环弹窗，也不回退为 `/usr/bin/security` 的第二次请求。主动导出旧配对配置仍可请求系统授权。密钥继续留在钥匙串；没有改成明文文件存储。跨版本延续钥匙串信任需要稳定签名身份，ad-hoc 包的代码哈希变化不能保证继承。

### Skill 自动连接配置

公开发现记录仅提供本机应用定位，不包含访问令牌。auto_profiles 中复用的令牌存储在现有 AES-GCM 配对存储内（Windows 密钥用 DPAPI，macOS 用钥匙串），按实际调用程序路径和客户端名区分。Skill 本身不读取此存储或直接访问资料库；应用辅助进程通过同一 MCP 权限层读取。首次确认、拒绝冷却、撤销及范围快照继续生效。安装 Skill 不等于已授权；本机终端执行能力不受 MCP 只读接口约束。

## 已退役的群安全数据

旧版群安全的侧库 `data/monitor/<账号 SHA-256>.sqlite`、报告/回执目录 `data/monitor-bridge/` 和模型配置 `data/monitor-local/` 可能包含聊天衍生资料。移除功能不会删除或迁移这些文件；新版不读取它们、不接收报告、不启动模型、不将旧结果暴露给 MCP。

聊天索引、媒体、关注范围、产品账号隔离、现有 AI 连接和授权不变。备份时仍按私有聊天资料保护旧监测文件，不提交源码或公开分发包。未来独立 Skill 仅通过用户授权的通用读取接口分析资料；独立 Skill 和外部定时任务不因本次源码改动而自动创建或被修改。

## Mac 自动媒体补全

Mac 的自动媒体队列在服务启动和消息增量进入后执行，覆盖当前账号已索引会话，遵守自动加载开关及逐消息设置。凭据仅从官方现有缓存只读解析，并与当前账号真实图片密文验证得到的密钥匹配；无法绑定账号时不发送下载请求，稍后重试。不会修改微信原件或启动微信窗口。下载只访问固定腾讯 HTTPS 服务，拒绝重定向，限制字节数、耗时和解码尺寸；校验 AES 填充、对应长度和消息/CDN 摘要。转发附件的密钥与下载引用不会传给 renderer 或 MCP。企业微信接口即使返回 HTTP 200 也可能只给出前 512 KiB；按 Content-Range 补齐，并校验连续偏移、总长与 ETag。服务器重新编码且缺少原件摘要的 JPEG，经 TLS、消息 AES 密钥、填充和系统图片解码检查后只按预览保存，绝不覆盖原件身份或绕过不匹配的服务端摘要。

队列及校验后的原件、表情、附件只保存在各资料库自己的 `data/` 下；普通诊断只记录固定错误码。独立图片解码进程不含网络协议，随包保留对应源码和构建选项。

Mac 本地旧表情只读解析当前账号的候选 UIN 文件名，派生独立 EMOTICON AES-CBC 密钥；UIN 文件名或正确填充均不足以判定成功，必须通过消息完整 MD5 与图片格式检查。表情包切片只采用当前账号已解密 emoticon 快照的偏移和长度，拒绝越界、符号链接及超限文件。只把验证后的原始图片写入 Noteford 缓存，不保存或输出表情密钥。

## Mac 单账号连接与后台解析

Mac 当前固定使用已选账号，不开放新增或切换入口，其他已保留资料库不删除。首次连接必须确认临时副本实际打开的账号库，再校验该账号密钥；不能用其他进程或磁盘已有库冒充本次登录。重新连接绑定当前账号。密钥验证后登记该账号，通讯录可读即开放关注引导，后续数据库继续后台解密和索引；部分读取不冒称全部完成。捕获失败或账号不符时保留原有密钥。

后台只处理当前账号，全部本机消息索引与关注范围分离；归档、索引、媒体、关注状态保持账号隔离。注册表写入使用 Mac 专用锁，请求绑定账号，桌面变化不扩大既有 MCP/CLI 授权。微信原始库仅只读快照；首次连接仍需用户完成临时副本登录，原版安装文件不修改。

## 产品账号会话

Noteford 通过主进程调用固定的 PERC HTTPS 地址，密码与验证码只用于本次认证，不写磁盘或日志。服务端验证邮箱验证码和邀请码后才创建统一 Accounts 用户；邀请码预留、消费和账号关联使用数据库事务，重复提交复用同一注册记录。产品会话、退出凭据及服务端已验证的账号身份一起使用 Electron safeStorage 加密保存在资料根 `data/runtime/product-account/product-account.enc`，身份绑定 API origin；系统安全存储不可用时拒绝保存登录。重启先恢复该身份自己的本地资料库，再后台核验会话；临时断网、代理或服务故障不退出已记住的账号，30 秒后自动重试，正常时每 5 分钟及系统唤醒时校验。服务端明确撤销、禁用或失效会话时锁定资料并清除保存的会话；Nexus 跨应用身份仍要求实时在线核验。旧版仅保存令牌的记录需成功在线验证一次完成迁移，不能从资料目录或网页缓存推断账号。退出不删除资料，离线退出会保存待撤销队列。

应用内找回密码发送纯验证码邮件，不包含浏览器链接；验证码一次性使用，完成后撤销该账号既有 Noteford 会话。Supabase 管理密钥及验证码摘要密钥仅存在服务端，禁止打进桌面包。开发版资料目录与日常安装版分离，且不发布日常连接发现文件。


## 产品账号与本机资料隔离

安装级目录仅保留加密产品会话和工作区归属表。资料工作区由受信账号接口返回的稳定用户 ID 与 API origin 共同确定；其他账号使用 `product-accounts/<摘要>/` 中独立的配置、资料库、索引、缓存、微信捕获状态及 AI 授权。旧资料原路径保留，仅允许管理员预先确认的归属邮箱首次通过服务端验证后绑定稳定 ID；不得把最后登录账号当作旧资料所有者。未确认的旧资料保持封存，新账号不会自动认领。

登录完成须等待工作区服务就绪。退出先撤销本次工作区租约、拒绝数据 IPC，再停止服务与远程 MCP、撤下发现记录、清空媒体映射及网页缓存并重载页面；迟到响应不可转入下一账号。HTTP 和独立 MCP 每次读取与返回均核验工作区和会话代次，旧连接不能继承重新登录后的租约。媒体响应不缓存。匿名本地入口关闭。

Mac 默认归档、密钥捕获文件跟随当前工作区；公开捕获接口不接受调用方指定目录。导入/预览拒绝其他工作区及其符号链接。新工作区的微信捕获钥匙串项、各 MCP 加密存储键分别命名，旧资料所有者继续使用旧项。此边界约束 Noteford 产品账号，不替代操作系统用户之间的文件权限或磁盘加密。

## 本机完整卸载

独立 Mac 卸载工具执行本机所有产品账号资料删除，不是仅当前账号退出。执行需要在卸载工具的原生确认框勾选并确认，先停止应用和同包服务，再删除应用自有数据库、消息副本、媒体、配置及专属钥匙串项目，重置本应用授权。此操作不可撤销。常规退出/升级不会执行清理。

删除范围为固定应用目录，拒绝符号链接祖先且不跟随目录内部链接；不会以“清理痕迹”为由扫描或删除微信原始目录、手动导出/备份、第三方 AI 客户端配置、云端账号或系统日志。失败会提示未完成，不宣称电脑绝对无痕。


### Mac 微信密钥存储修复（2026-10-21）

Mac 数据库密钥及按资料库区分的候选/图片密钥只持久保存于登录钥匙串，沿用产品工作区隔离。旧 `keys.json`、`candidate_keys.json`、`image_keys.json` 在格式校验、合并、钥匙串写入及回读一致后删除；拒绝访问、冲突或写入失败保留旧文件并明确失败，不回退到明文读取。密钥不会通过命令行参数传给 `security`。正常同步与媒体读取改用钥匙串；MCP 继续读取原索引并执行原授权，不向 AI 提供微信密钥。

取钥使用独立的受限权限临时文件，在成功、失败和取消后清理，启动/同步时清理遗留捕获文件。捕获租约避免清理仍在使用的 LLDB 文件，带 PID 的 hook 文件保留活跃写入者。原始微信库、归档、索引和媒体不属于清理范围。强制杀进程或断电仍可能留下临时文件，下一次运行再清理；普通删除不承诺抹除磁盘快照、旧备份或已复制的文件。钥匙串保护静态密钥，不能代替对已解密归档及当前操作系统会话的保护。已按用户授权更新日常 Mac 安装版，迁移、正常退出重开与真实同步验收见 STATUS。
