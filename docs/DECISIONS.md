# 重要架构决策

适用对象：维护者。本文件集中记录影响产品结构、数据归属和接口边界的决定。每条包含背景、决定和后果；已采纳的决定保留历史。未来改变方向时在本文件**追加新编号**，注明取代关系，不为每次任务新建 ADR 文件。

> 历史范围提示（2026-10-23）：早期 D-001～D-004 描述 Windows 初版，不覆盖当前 Mac 单微信账号、Data 专用目录、钥匙串存储及产品工作区租约。当前执行规则见 [DEVELOPMENT](DEVELOPMENT.md)、[ARCHITECTURE](ARCHITECTURE.md) 与 [CONTRACTS](CONTRACTS.md)。此处保留决策演变，不重演旧迁移或更新步骤。

## D-001 注册前预览本机账号

- 状态：已采纳。
- 背景：一个微信数据根目录可能含多个账号，目录标识不足以让用户可靠判断身份。
- 决定：读取微信配置路径及少量常见位置，先以联系人和头像数据库的临时只读快照预览身份。用户选定后才注册资料库；自动发现失败保留手动选目录入口。密钥不可用时显示目录标识和不可用状态，不猜昵称头像。
- 后果：发现可能花数秒，未登录账号身份不一定可读；不递归扫遍磁盘，也不自动注册所有账号。微信路径或数据库结构变化时复核。

## D-002 程序与数据支持单文件夹布局

- 状态：已采纳；更新和迁移仍待多机验收。
- 背景：普通 NSIS 安装与单文件夹试用对数据根位置要求不同，数据还包含明文索引和密钥。
- 决定：普通安装默认用 `%LOCALAPPDATA%\WeChatLocal`；`app/.portable-layout` 标记或既有父目录配置使程序位于 `<根目录>/app/`、数据位于父目录。开发运行时使用源码目录，不自动迁移数据。
- 后果：单文件夹根目录必须可写并受保护；移动程序、标记或配置可能改变数据根。更新仅应替换程序，回滚前须核对数据格式。

## D-003 每小时累计原始消息，按关注解析

- 状态：已采纳。
- 背景：只在关注后读取实时微信库，会失去曾经观察到但后来从来源删除的历史；一个用户还可能添加多个账号。
- 决定：桌面服务运行时，启动后及默认每 3600 秒刷新所有注册账号。源库变化时复制快照；每个账号把已观察到的原始消息行累计写入独立归档，不受关注状态影响。仅已关注会话进入可搜索索引；后来关注时从归档补建。两代加密快照和一代解密快照的保留，与累计归档分开。
- 后果：未关注消息也保存在本机，增加空间和保护责任；不无限保存整库小时快照。服务停止或两次成功快照之间消失的内容不能保证恢复。媒体预取只针对已关注会话，默认最近 14 个本地日历日，可设 1–365 天。

## D-004 MCP 嵌入现有服务并保持只读

- 状态：已采纳。
- 背景：AI 客户端需要 MCP，但桌面 HTTP API 持有动态端口、Token 和可写的当前资料库状态。
- 决定：以官方 MCP Python SDK 经 stdio 暴露五个只读工具。每次请求用稳定 `library_id`，直接查询已有索引；作为同一打包服务的 `--mcp` 启动模式，不新增安装产品。
- 后果：桌面关闭后仍可读已有索引，但不能刷新或关注。索引结构变化要复核工具；当前无筛选消息分页缺陷见 [STATUS](STATUS.md)。

## D-005 群聊日报并入单一桌面应用（2026-10 已整体移除，见 D-REMOVE-DIGEST）

- 状态：已采纳。原历史文档与 D-001 重复使用 `ADR-0001`，此次重组统一为独立编号，决定未变。
- 背景：第二个日报安装版会复制程序、资料库和快捷方式，而用户只需要一个持续升级的应用。源码仓库私有，安装包允许公开供更新。
- 决定：日报共用 WeChat Local 的账号、Python 服务、Electron 界面与数据根。模型调用由用户明确开启；公开 GitHub 更新仓库只放安装包与更新元数据，用户选择重启安装。
- 后果：一个发布版本承载阅读、筛选、日报和 MCP。彻底退出或关机时日报调度暂停；未签名安装包和未完成的兼容、隐私、法律验收仍限制公开商用。

## D-006 消息筛选改用本地 Laya（已由 D-008 取代）

- 状态：开发版已采纳；尚未发布正式安装包。
- 背景：Jev 通过外部 API 处理已关注会话内容，需要密钥并会使聊天数据离开本机。
- 决定：用开源 Laya 的多语言权重在 Python 服务内进行消息评分；首次启用下载权重，之后的推理使用本机模型。旧 `jev_enabled` 不自动迁移为 `laya_enabled`，旧评分缓存用新的评估版本隔离。日报模型仍由用户单独配置。
- 后果：筛选无需 API Key，但首次下载、磁盘占用和本机推理资源增加。Laya 零样本中文筛选质量须用真实样本人工验收；不承诺与 Jev 分数一致。回退时关闭 Laya 设置即可继续规则筛选，原始消息与旧缓存均保留。


## D-007 官方 MCP 优先，分析和自动化由 AI 客户端负责

- 状态：已采纳；开发版实现，未发布。维护者负责；补充 D-004 的权限与增量协议，替代其无范围限制的本机读取方式。
- 背景：用户希望任意支持本机 MCP 的 AI 能读取授权微信消息，并在 AI 平台定义分析、定时检查和提醒。现有 MCP 缺少访问范围与可靠增量游标。
- 决定：首版只交付 stdio MCP，复用应用安装的 Python 服务；不增加独立 CLI/API 产品。设置页为连接选择单个账号和最多 500 个明确会话，导出官方本机插件或配置。每次工具调用重新读取授权；没有授权默认拒绝。分析规则、任务状态、游标保存、自动化、通知均归 AI 客户端。
- 增量：索引拥有 mcp_stream / mcp_changes 和三个消息触发器，只追加事件元数据；同事务记录消息插入、内容版本变化及删除。旧索引在应用正常打开时初始化历史事件；MCP 不迁移数据。游标绑定资料库、授权会话集和索引代号，依据入库变化序号而非发送时间推进。事件的 current 是读取时现态，不承诺历史内容快照。
- 替代方案：时间戳轮询会漏掉补采集；MCP 临时写入同步状态会破坏只读边界；三个入口同时开发增加当前没有需求的维护成本。
- 后果：本机协议授权不构成同 Windows 用户下的文件系统沙箱；有直接磁盘权限的程序仍可能绕过协议。导出插件与本机安装位置绑定，移动安装目录后重新导出。关闭窗口后可读已有索引；数据新鲜度仍受应用采集影响。远端 AI 和云端自动化尚未接入。
- 回滚：撤销连接后停止新的读取；回滚代码不删除已有数据，旧程序可忽略新增表，已有触发器继续记录变化。不要手工删除序列记录或只恢复部分表；重建索引后应重新建立游标。
- 复核条件：需要远程 MCP、多客户端凭据隔离、事件清理、恢复旧备份或公开发布插件时重新审查权限、游标失效和打包兼容性。

## D-008 移除本地 Laya 筛选

- 状态：已采纳，0.3.7；用户明确要求完全移除。
- 决定：删除设置、模型下载、筛选侧栏、评分与补跑任务、专用接口和依赖；不以隐藏开关替代删除。旧专用接口返回 404，旧配置键不再读取。
- 边界：消息、搜索、媒体及只读 MCP 保留；消息价值判断交给 AI 客户端。
- 数据：本机更新清除专用模型、配置键和评分缓存，不删除消息索引、归档或 MCP 授权。
- 回滚：保留升级前应用和数据备份；恢复旧版须整套恢复相应程序与配置，模型可重新下载。

## D-009 本机日常改动免安装

- 状态：已采纳，用户选择本机改完立即生效，非远端分发。
- 决定：增加显式数据根的源码运行入口，以 Vite 提供界面热刷新；受限文件监视器在语法检查后请求 Electron 正常退出，再启动新代码。保持原数据根和应用身份，默认开发版仍隔离。
- 替代：每次打包安装无法满足日常迭代速度；远程签名更新包需要另一套发布体系，超出本次范围。
- 后果：依赖本机源码、Node/Python/Electron 环境；后台更新仍有短暂重启。占用端口拒绝启动，代码语法错误不关闭当前实例，正常退出停止守护进程；不观察数据和密钥。
- 回退：退出源码运行时，再通过保留的安装版快捷方式启动 0.3.7，资料库不迁移。
- 复核：未来向其他电脑分发或引入数据库迁移时，单独审查签名、兼容和恢复流程。

## D-010 客户端接入渲染采用产品内 vendored 公共模块

- 状态：已采纳，源码实现；安装包仍按正式发布流程单独验收。
- 背景：Noteford 与其他本机产品都要生成 stdio MCP 的 JSON/TOML 配置、可选品牌 Skill 安装提示和只读状态验收说明。各自手写序列化容易产生转义差异，但授权、传输和产品语义并不相同。
- 决定：在 `desktop/electron/shared/client-setup.cjs` 保存经审查的公共模块副本，只复用客户端配置渲染和接入提示词骨架。Noteford 继续由 `mcp-prompt.cjs` 提供产品名、服务器名、Skill 路径、验证码配对步骤和 `list_libraries`/`get_status` 验收规则；不把授权、凭据、持久配置或传输实现移入公共模块。公共副本随源码和应用打包，不在运行时加载其他产品仓库、全局模块或网络资源。
- 后果：公共模块升级需显式复制、审查版本并运行产品自己的提示词与配对测试。正式包把 `noteford` Skill 作为 asar 外只读资源提供路径；Skill 是可选说明层，MCP 不依赖其安装。旧 `wechat-local` Skill 和服务器名保留兼容入口，不删除用户已安装副本。
- 回滚：恢复原提示词渲染并移除新增外部 Skill 资源即可；MCP 服务、配对存储、授权文件和用户数据无需迁移。

## 内容提取与 AI 判断分离

内容筛选首版复用现有索引和解码器，以只读查询生成素材条目，不增加资料库迁移或模型依赖。分类和原链接由确定性规则产生，AI 的研究与价值判断保持在客户端。相同类型的相同完整链接或附件摘要合并展示，未修改查询参数或丢弃出处。可回退入口和接口代码，原消息与归档不受影响。大资料库查询成本随消息数量增长，后续若出现性能瓶颈再引入持久提取索引。

## 2026-10-11：统一顶部工具栏与会话媒体范围

Windows 使用 Electron 原生 titleBarOverlay，移除额外标题栏文字；按钮、日历和搜索为非拖动区域，空白仍可拖动，原有关闭到托盘行为不变。

媒体范围归属于每个资料库的 `data/media_ranges.json`，以会话 ID 为键；首次添加时间复用注册表 created_at，不推测微信注册日。默认起始日为该本地日期减 14 天，结束日 null 表示至今；显式结束日包含当日。保存采用锁与原子替换，不迁移索引、不清除缓存；GET/POST 必须携带 library_id 和 conversation，防止切换账号时错写。预取与状态统计复用同一个日期规则，旧独立 CLI 天数参数仍保留；手动阅读历史媒体保持按需解析。

回退时恢复本轮源码即可；新增范围文件保留，旧源码会忽略，不删除任何资料库或缓存。


## 2026-10-11：读取本地红包终态用于显示折叠

已采纳：红包领取状态独立于聊天 XML，使用本账号 general.db/redEnvelopeTable 的受限只读适配器，复用既有快照和解密方法。映射依据字段实查及上游原生状态研究（https://github.com/fzlzjerry/wechat-antirecall/blob/main/Docs/red-packet-269624.md 和 https://github.com/AvengersWeChat/PadChat-SDK/blob/master/docs/index.md）；这不是微信公开稳定接口。限定已知类型和终态，其余未知；微信版本或字段变化时复核，禁止将未知码当作不可领取。

不采用网络查询、领取接口、内存 hook 或数据库写回。状态仅影响可展开的界面分组；禁用该读取器即可回退为 XML 过期时间和专属对象判断，无数据迁移。当前本机读取与准确关联已验证；没有操作真实领取来验证跨设备状态写入延迟。


## 2026-10-11：按内容标识恢复本机已有原图

已采纳：实查发现同一图片在不同消息下使用不同本地文件名，原来的消息目录查找会漏掉已下载原图。保留直接路径优先，以同账号微信资源索引作为回退，验证解密后内容哈希再缓存到目标消息名下。资源索引读取器复用已有只读快照和解密能力，不增加外部下载、数据库迁移或 MCP 源文件读取权限。

不以缩略图相似度或大小关联，不在请求中递归扫描所有媒体。缺失映射、未知布局和失败快照保持原有回退；微信资源表结构变化时复核。回退可移除解析器的资源查询接入，保留全部源文件和缓存，无须回滚数据。


## 2026-10-11：独立下载文件与微信本地缓存分离

已采纳：已验证的独立下载保存在资料库 media-cache/downloaded，按账号与消息 UID 的组合哈希隔离，清单只保存关联、类型、完整性摘要及校验来源，不保存 CDN 凭据或远程地址。解析器首先验证清单和文件 SHA-256，再返回 ready，避免原始微信缓存缺失导致每次重新显示缩略图。消息原文件与 CDN 替代版本分别记录 message_original/cdn_variant，后者不能声称匹配旧消息内容哈希。

网络/会话提取仍留在显式本机实验入口，不在普通消息渲染、后台同步或只读 MCP 中自动触发。回退时移除 MediaResolver 的 retained_download 接入即可恢复原读取顺序；保留源目录及独立缓存，不需要删除或迁移数据。


## 2026-10-11：显式媒体获取接入独立 CDN 下载

状态：已采纳。维护者：Noteford。取代上一节“网络仅留在实验入口”的限制；原缓存隔离与回退规则继续有效。

已有真实双样本证明：未缓存的原图及完整视频可以使用当前账号的登录会话直接从腾讯 CDN 获取。保留单一显式入口 `/api/v1/media/recheck`：检查资料库、消息和关注状态，先复用校验过的独立缓存或本地完整文件，缺失才下载；消息列表、预取和只读 MCP 不自动发起下载。业务接入位于 service，协议和下载校验位于 cdn_download，会话只读恢复位于 cdn_session；无新增依赖、账号登录流程或微信写操作。

会话恢复验证完整 MMKV 配置路径、CRC、目标账号用户名及 UIN，再使用匹配账号的请求字段；只在内存保留凭据。网络固定 HTTPS 腾讯域名，禁止重定向；自动下载按用户选择的 20／30／50 MiB 阈值筛选，全部下载与手动下载不设文件大小上限；每个 CDN 分块有独立的 30 秒请求预算、每块最多三次网络尝试，持续传输不受固定总时长限制。Windows 传输器保留全进程一个下载的并发约束，Mac 后台队列串行处理。文件分块落盘，校验后原子转入缓存；磁盘余量按剩余字节检查。分块顺序、总长度、AES 填充和内容摘要均须通过，已观察到的视频替代类型 9 还必须匹配 CDN 摘要，不能宣称匹配旧原文件。失败不提交缓存清单、不覆盖缩略图；临时文件正常退出清理。应用崩溃后遗留的 `.download-*` 目录不会被识别为可用媒体。

未采用渲染时自动联网或无界重试，避免无意批量下载与重复占用；未增加后台队列或断点续传，失败后下一次显式请求重新开始，成功文件复用持久缓存。UI 显示获取中、防止重复点击、翻译固定错误码，切换消息/账号后丢弃旧请求结果。

风险与复核触发：依赖当前 Windows 微信/MMKV 非公开布局，升级或登录状态变化可使会话恢复失败，届时应复核适配器，不能绕过账号绑定。首次获取仍需要该账号处于登录状态。回退仅移除 service.recheck_media 的网络回退及前端获取文案；保留已校验下载缓存及所有源数据，不迁移或删除数据。


## 2026-10-11：按会话媒体范围自动补全
